# Code Review - 详细参考文档

## 分析维度指导

在生成报告时，应该从以下维度分析每个文件的改动：

### 1. 业务逻辑变更
- **流程变化：** 订单流程、支付流程、审核流程等
- **规则调整：** 计算规则、判断条件、业务规则
- **状态变更：** 状态机、流转逻辑

### 2. 界面展示变更
- **文案修改：** 按钮文案、提示信息、帮助文档
- **样式调整：** 布局、颜色、字体、间距
- **交互优化：** 点击行为、页面跳转、弹窗逻辑

### 3. 数据交互变更
- **API 调用：** 新增、修改、删除接口
- **参数变化：** 请求参数、返回结构
- **数据处理：** 数据转换、格式化、校验

### 4. 配置变更
- **环境配置：** API 地址、开关控制
- **路由配置：** 路由规则、权限控制
- **常量定义：** 业务常量、枚举值

### 5. 兼容性影响
- **版本兼容：** 向前兼容、向后兼容
- **数据迁移：** 是否需要迁移脚本
- **依赖变更：** 第三方库升级

### 6. 性能影响
- **性能优化：** 算法优化、资源优化
- **潜在性能问题：** 循环嵌套、大数据处理

## 特殊处理规则

### 1. 开发调试代码
对于以下类型的改动，可以简要说明而不详细展开：
- 测试账号配置
- 开发环境专用代码
- console.log 等调试代码
- 注释修改（除非是重要文档注释）

### 2. 连锁影响标注
当改动可能引起连锁反应时，使用特殊标记：

```markdown
⚠️ **连锁影响警告**
此改动修改了公共组件 PriceCard.vue，影响范围包括：
- 订单页面
- 详情页面
- 首页卡片
- 个人中心
共计 15+ 个调用位置
```

### 3. 破坏性变更标注
对于可能破坏现有功能的变更，特别标注：

```markdown
🔥 **破坏性变更**
订单提交接口参数结构变更，旧版本客户端可能无法正常使用。
需要：
- [ ] 确认最低兼容版本
- [ ] 通知用户升级
- [ ] 准备回滚方案
```

## 改动类型标签体系

使用统一的标签来标识改动类型：

| 标签 | 含义 | 优先级 |
|------|------|--------|
| `[功能新增]` | 新增功能或模块 | 高 |
| `[功能优化]` | 改进现有功能 | 中 |
| `[Bug修复]` | 修复缺陷 | 高 |
| `[文案优化]` | 文案调整 | 低 |
| `[样式调整]` | UI样式修改 | 低 |
| `[配置变更]` | 配置项修改 | 中 |
| `[接口调整]` | API接口变更 | 高 |
| `[性能优化]` | 性能改进 | 中 |
| `[重构]` | 代码重构 | 中 |
| `[全局影响]` | 影响多个模块 | 高 |

## 测试优先级判定标准

### 🔴 高优先级 (必须测试)
- 核心业务流程变更
- 接口参数结构调整
- 新增业务渠道/类型
- 破坏性变更
- 权限/安全相关

### 🟡 中优先级 (重点测试)
- 配置项调整
- 全局文案修改
- 数据计算逻辑
- 页面流程优化

### 🟢 低优先级 (可选测试)
- UI细节调整
- 代码重构（不改变功能）
- 开发调试代码
- 注释文档更新
