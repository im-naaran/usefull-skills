## requirements.md 摘要

```markdown
# 需求规格说明书

> 状态：已确认

## 背景

当前登录流程仅支持密码登录，需要增加短信验证码登录。

## 功能需求

### R-01: 发送验证码

当用户输入手机号并点击获取验证码时，系统应当调用短信验证码发送接口。

### R-02: 验证码登录

当用户输入手机号和验证码并提交时，系统应当完成登录。

## 验收标准 / 人工确认点

### AC-01

Given 用户输入合法手机号
When 点击获取验证码
Then 页面展示倒计时，且发送验证码请求参数正确

## 范围外

- 不调整密码登录流程。

## 待确认问题

无
```

## 需求阶段存在阻塞问题时的回复示例

```text
Phase 1 已生成需求规格说明书草稿。

当前需求中仍有会影响设计和任务拆解的问题，先不进入 Phase 2。

需确认后再继续

1. 是否需要保留密码登录入口？
   为什么需要确认：这会影响登录页入口布局、状态流和回归范围。
   影响：如果保留，需要设计登录方式切换；如果不保留，需要调整范围外内容和验证重点。

2. 短信验证码发送是否有图形验证码或风控前置要求？
   为什么需要确认：这会影响接口参数、错误处理和任务拆分。
   影响：如果有前置校验，需要增加相关需求、设计和验证点；如果没有，可按普通发送流程推进。

请先明确以上问题；确认后我再进入 Phase 2: 设计。
```

## design.md 摘要

```markdown
# 技术设计

> 状态：已确认

## 方案概述

复用现有登录页，在登录方式区域增加短信验证码模式。

## 涉及模块

- src/api/login.ts
- src/views/login/index.vue

## 接口与类型

- sendSmsCode(params: { phone: string })
- loginBySmsCode(params: { phone: string; code: string })

## 公共能力复用评估

| 能力类型 | 检索范围 | 现有实现 | 差距 | 决策 | 影响 |
|----------|----------|----------|------|------|------|
| 请求封装 | src/api、src/utils/request | 已有统一请求封装和错误处理 | 不缺能力 | 复用 | 保持现有接口调用和错误展示方式 |
| 倒计时逻辑 | src/hooks、src/utils、登录页相关组件 | 未发现可复用验证码倒计时能力 | 缺少短信验证码场景的倒计时状态管理 | 新建（局部实现） | 仅影响登录页，不新增公共 Hook |

## 实现约束

### 注释策略

- 接口参数映射存在后端字段差异时补充原因说明。
- 倒计时边界处理需要注释说明，普通表单赋值不添加注释。

### 封装边界

- 短信验证码模式切换和表单校验直接放在登录页现有逻辑中。
- 倒计时逻辑仅当前页面使用，不抽取公共 Hook。

## 需求追踪

| 需求 | 设计点 |
|------|--------|
| R-01 | 新增 sendSmsCode |
| R-02 | 新增 loginBySmsCode 并接入登录页 |

## 待确认问题

无
```

```markdown
- 新增 sendSmsCode API

- 本任务为 API 封装，无单独页面效果；真实接口参数在 UI 联调任务中验证。
- 验证接口异常时沿用现有错误提示链路。

**待确认问题：** 无
```
