## requirements.md

```markdown
# 需求规格说明书

> 状态：草稿

## 背景

## 目标

## 功能需求

### R-01: ...

当...
系统应当...

### R-02: ...

## 非功能需求

### NFR-01: ...

## 验收标准 / 人工确认点

### AC-01

Given ...
When ...
Then ...

## 范围外

## 待确认问题
```

要求：

- 需求使用 `R-xx` 编号。
- 能用 EARS 表达时，优先使用"当...系统应当..."。
- 非功能需求只写和本功能强相关的内容。
- 待确认问题会阻塞设计或实现时，先问用户。

## tasks.md

```markdown
# 任务拆解

> 状态：草稿

- [ ] task-01: [API] 增加短信验证码接口封装
- [ ] task-02: [UI] 增加短信验证码表单
- [ ] task-03: [State] 增加验证码倒计时状态

## task-01: [API] 增加短信验证码接口封装

**追踪需求：** R-01, R-02
**依赖任务：** 无
**修改范围：** src/api/login.ts
**完成标准：**
- 新增发送验证码方法
- 新增验证码登录方法
- 复用现有请求封装和错误处理

**自动化验证：**
- 按项目实际填写可执行的验证命令（编译 / 构建 / 烧录自检 / 测试 / 静态检查等），无则写"无"

**人工验证关注点：**
- 验证发送验证码接口参数正确
- 验证接口异常时沿用现有错误提示
```

要求：

- 单个任务保持小粒度，预计 30 分钟内能完成。
- 任务应可独立回滚。
- 依赖只能指向编号更小的任务，禁止循环依赖；无依赖时写"无"。
- 自动化验证按项目实际填写可执行命令（不限语言或平台），无法自动验证时写"无"，并在人工验证关注点补充说明。
- 完成一个任务后更新勾选状态。
- 人工验证关注点写在对应任务下，不默认创建独立测试报告。

## changelog.md

```markdown
# 变更记录

## 2026-06-08

- 创建需求规格说明书。
- 完成技术设计。
- 完成 task-01。
```

要求：

- 按时间顺序追加，不覆盖既有记录。
- 只记录和当前功能规格、设计、任务、实现相关的关键变化。
- 需求变更时记录变更原因和影响范围。
